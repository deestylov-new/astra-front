# Астра

**Астра** — демонстрационное web-приложение личного помощника для путешественника, который работает удалённо в IT. Сервис объединяет поездки, финансы, цели, накопления и рабочие задачи в одном спокойном и понятном интерфейсе.

Проект реализован как frontend-прототип на React с демонстрационными данными. Серверная часть, база данных и настоящие интеграции пока не подключены.

## О проекте

Цель Астры — уменьшить количество разрозненных сервисов, которыми пользуется digital nomad. Вместо отдельных приложений для билетов, бюджета, накоплений, чек-листов и задач пользователь получает единое рабочее пространство.

В текущем прототипе можно:

- просматривать общую картину дня;
- контролировать ближайшие поездки и бронирования;
- отслеживать доходы, расходы и регулярные платежи;
- планировать события и разбивать их на шаги;
- управлять финансовыми целями;
- вести личные и рабочие задачи на agile-доске;
- настраивать профиль, уведомления и подключения к другим сервисам.

## Основные разделы

### Главная

Обзорный экран собирает наиболее важную информацию из всех разделов:

- ближайшую поездку с перелётом, отелем и погодой;
- состояние месячного бюджета;
- расходы по основным категориям;
- последние финансовые операции;
- задачи в фокусе на сегодня;
- системные уведомления и рекомендации Астры.

Главная предназначена для быстрого ежедневного просмотра без необходимости переходить в каждый раздел отдельно.

### Бронирования

Центр управления поездками, билетами и проживанием.

В разделе представлены:

- количество активных поездок и подтверждённых бронирований;
- сумма расходов на путешествия;
- готовность документов;
- временная линия перелётов, отелей, транспорта и мероприятий;
- фильтры по типам бронирований;
- маршрут поездки;
- страховка, билеты и подтверждения проживания.

Пользователь может создать бронирование отеля, перелёта или транспорта через отдельное диалоговое окно.

### Бюджет

Финансовый планировщик для контроля доходов и расходов.

Раздел включает:

- доходы за выбранный период;
- фактические расходы;
- свободный остаток после обязательных платежей;
- сумму регулярных операций;
- график изменения доходов и расходов;
- прогноз баланса от Астры;
- план и факт по категориям: жильё, еда, транспорт и подписки;
- календарь ближайших списаний и поступлений;
- переключение периода между месяцем, кварталом и годом.

### Цели и события

Инструмент для подготовки крупных событий: путешествий, переездов, конференций и других долгосрочных планов.

Каждое событие может содержать:

- дату и срок подготовки;
- общий прогресс;
- бюджет и накопленную сумму;
- количество участников;
- маршрут;
- чек-лист задач;
- связанные бронирования и документы.

В демо-данных показаны поездка по Исландии, переезд в Лиссабон и Web Summit.

### Дела

Agile-доска для личных и рабочих задач.

Задачи распределены по этапам:

1. Бэклог.
2. В работе.
3. На проверке.
4. Готово.

Карточки содержат категорию, срок, исполнителя и прогресс подзадач. Доступны фильтры для рабочих, личных и туристических задач.

### Копилка

Раздел помогает копить на конкретные цели и видеть реалистичный срок их достижения.

Возможности демо-экрана:

- общий баланс накоплений;
- прогресс всех финансовых целей;
- отдельные копилки для путешествия, техники и финансовой подушки;
- ручное пополнение;
- автоматическое перечисление процента от дохода;
- округление покупок в пользу накоплений;
- прогноз достижения целей;
- рекомендации по оптимизации подписок.

### Настройки и интеграции

Раздел для персонализации сервиса.

В нём предусмотрены:

- личные данные пользователя;
- домашний город и часовой пояс;
- основная валюта;
- настройки уведомлений;
- безопасность;
- тариф и оплата;
- управление интеграциями.

В интерфейсе показаны демонстрационные подключения Google Calendar, Telegram, Tinkoff и Notion. Переключатели меняют только локальное состояние интерфейса и не подключаются к реальным API.

## Интерактивные сценарии

### Меню «Запланировать +»

Основное быстрое действие в верхней панели. Открывает четыре сценария:

- новое бронирование;
- новое событие;
- новая задача;
- новая цель накопления.

Для каждого сценария используется собственное модальное окно с соответствующими текстами и полями.

### Вертикальная навигация

Боковое меню можно свернуть до компактного режима. В нём остаются только иконки, а названия разделов показываются во всплывающих подсказках при наведении.

На мобильных устройствах меню превращается в выезжающую панель с затемнением фона.

### Поповеры и уведомления

В интерфейсе предусмотрены:

- панель уведомлений;
- контекстное меню ближайшей поездки;
- меню быстрого планирования;
- всплывающие подтверждения действий;
- подсказки для компактной навигации.

Поповеры закрываются по клику вне области. Диалоговые окна также можно закрыть клавишей `Escape`.

### Локальные состояния

Без backend уже работают демонстрационные взаимодействия:

- отметка задач и пунктов чек-листа;
- фильтрация бронирований;
- выбор периода бюджета;
- переключение интеграций;
- раскрытие меню и диалогов;
- переходы между всеми разделами;
- визуальные подтверждения действий.

После перезагрузки страницы эти изменения сбрасываются.

## Дизайн и визуальный стиль

Интерфейс вдохновлён продуктовыми принципами Apple, но сохраняет собственный характер Астры.

### Основные принципы

- **Спокойная технологичность.** Интерфейс не перегружен декоративными элементами и оставляет достаточно свободного пространства.
- **Контекст вместо шума.** На экране одновременно отображается только информация, необходимая для текущей задачи.
- **Мягкая глубина.** Карточки отделяются от фона тонкими границами, лёгкими тенями и полупрозрачными поверхностями.
- **Единая иерархия.** Заголовки, метрики, подписи и служебные статусы имеют стабильные размеры и контраст.
- **Понятная обратная связь.** Наведение, нажатие и изменение состояния сопровождаются визуальной реакцией.

### Цветовая система

Основная палитра построена на природных оттенках:

- тёмный хвойный зелёный используется для ключевых действий;
- светлые серо-зелёные оттенки формируют фон и вторичные поверхности;
- белый используется для карточек и активных элементов;
- приглушённые синий, оранжевый и фиолетовый обозначают категории данных;
- зелёный показывает успешные состояния и положительную динамику.

Такая палитра поддерживает ассоциации с путешествиями, спокойствием, надёжностью и финансовой осознанностью.

### Типографика

Используется шрифт **Manrope** с системными fallback-шрифтами. Он подключается через Google Fonts в `src/index.css`.

Типографическая иерархия включает:

- крупные заголовки с немного уменьшенным межбуквенным интервалом;
- компактные заголовки карточек;
- прописные служебные подписи с увеличенным трекингом;
- спокойный вторичный текст серо-зелёного цвета;
- табличные финансовые значения с повышенным визуальным весом.

### Карточки и поверхности

Большинство данных размещается в карточках с:

- радиусом скругления от 12 до 25 пикселей;
- тонкой нейтральной границей;
- мягкой тенью;
- светлым или полупрозрачным фоном;
- увеличенной тенью и небольшим смещением при наведении.

Фотографии используются точечно — только там, где они усиливают эмоциональный контекст путешествия.

### Анимация

Анимации короткие и функциональные:

- плавное появление страниц;
- масштабирование и смещение поповеров;
- мягкое раскрытие модальных окон;
- сворачивание боковой панели;
- заполнение прогресс-баров и круговых индикаторов;
- микроанимации кнопок и стрелок;
- лёгкий zoom фотографий при наведении.

Для большинства переходов используются длительности около `180–350ms` и плавные easing-кривые. Более медленная анимация фотографий создаёт эффект глубины без отвлечения от данных.

## Адаптивность

Интерфейс рассчитан на desktop, tablet и mobile.

### Desktop

- постоянная боковая навигация;
- многоколоночные дашборды;
- полноценная agile-доска;
- компактный режим меню для расширения рабочей области.

### Tablet

- финансовые и информационные блоки перестраиваются в две колонки;
- сложные композиции переходят в вертикальную структуру;
- сохраняется боковое меню уменьшенной ширины.

### Mobile

- боковая панель открывается поверх контента;
- статистика перестраивается в компактную сетку;
- agile-доска получает горизонтальную прокрутку;
- поповеры занимают доступную ширину экрана;
- большие карточки и формы переходят в одну колонку;
- второстепенная информация скрывается или упрощается.

Основные breakpoint-правила находятся в `src/index.css`.

## Технологии

- [React 19](https://react.dev/) — компоненты и интерактивное состояние;
- [TypeScript](https://www.typescriptlang.org/) — типизация;
- [Vite 8](https://vite.dev/) — dev-сервер и production-сборка;
- [Tailwind CSS 4](https://tailwindcss.com/) — базовый CSS pipeline и utilities;
- обычный CSS — основная визуальная система и адаптивность;
- [oxfmt](https://oxc.rs/docs/guide/usage/formatter.html) — форматирование исходников.

Дополнительная библиотека иконок не используется. Иконки реализованы как локальные SVG-пути внутри React-компонента.

```text
astra-front/
├── public/
│   └── favicon.png       # Иконка сайта
├── src/
│   ├── App.tsx           # Всё приложение: страницы, компоненты, демо-данные и состояния
│   ├── index.css         # Глобальные стили, дизайн-система, анимации и адаптивность
│   ├── main.tsx          # Точка входа React и подключение глобальных стилей
│   └── vite-env.d.ts     # Типы окружения Vite
├── .gitignore            # Файлы, исключённые из Git
├── index.html            # HTML-оболочка с корневым элементом приложения
├── package.json          # Зависимости и команды проекта
├── pnpm-lock.yaml        # Зафиксированные версии зависимостей
├── tsconfig.json         # Настройки TypeScript
├── vite.config.ts        # Настройки Vite, React, Tailwind CSS и alias `@`
└── README.md             # Документация проекта
```

### `src/App.tsx`

Основной файл приложения. Он содержит:

- SVG-компонент `Icon` и набор используемых иконок;
- конфигурацию боковой навигации;
- демонстрационные финансовые операции;
- переиспользуемые компоненты метрик и заголовков;
- модальные окна планирования;
- главную страницу;
- страницы бронирований, бюджета, событий, дел, копилки и настроек;
- локальные состояния React;
- обработчики кликов, фильтров, переключателей и уведомлений.

Для production-проекта этот файл целесообразно разделить на директории `components`, `pages`, `data` и `features`. В демо-версии он сохранён единым, чтобы интерфейс было проще запускать и переносить.

### `src/index.css`

Содержит всю визуальную систему приложения:

- базовую палитру и типографику;
- стили боковой и верхней навигации;
- карточки, таблицы, графики и прогресс-индикаторы;
- модальные окна и поповеры;
- agile-доску;
- формы и переключатели;
- hover-, focus- и active-состояния;
- keyframe-анимации;
- адаптивные правила для планшетов и телефонов.

### `src/main.tsx`

Создаёт React root, подключает `App` и импортирует `src/index.css`.

### `index.html`

Минимальная HTML-оболочка Vite. Содержит элемент `#root`, в который монтируется React-приложение.

### `vite.config.ts`

Подключает:

- React plugin;
- Tailwind CSS v4 plugin;
- alias `@`, указывающий на директорию `src`.

Конфигурация независима от Figma Make и подходит для локального запуска или размещения на обычном frontend-хостинге.

### `package.json`

Описывает зависимости и четыре команды:

- `dev`;
- `build`;
- `preview`;
- `format`.

### `pnpm-lock.yaml`

Фиксирует точные версии пакетов, чтобы установка была воспроизводимой в локальном окружении и CI.

## Запуск проекта

Требуется Node.js 20+ и pnpm.

```bash
git clone https://github.com/deestylov-new/astra-front.git
cd astra-front
pnpm install
pnpm dev
```

После запуска Vite выведет локальный URL приложения в терминале.

## Доступные команды

```bash
# Запуск dev-сервера с hot reload
pnpm dev

# Проверка и production-сборка
pnpm build

# Локальный просмотр production-сборки
pnpm preview

# Форматирование исходников
pnpm format
```

Production-файлы создаются в директории `dist/`.

## Данные и внешние ресурсы

Все данные в приложении демонстрационные и описаны непосредственно в React-компонентах.

Внешние ресурсы:

- фотографии путешествий загружаются с Unsplash;
- Manrope загружается через Google Fonts.

Для полностью автономной или production-версии изображения и шрифты можно разместить локально или подключить через собственный CDN.

## Текущие ограничения

- нет backend и базы данных;
- нет регистрации и авторизации;
- данные не сохраняются после перезагрузки;
- бронирования не связаны с реальными туристическими сервисами;
- банковские операции являются демонстрационными;
- интеграции не используют внешние API;
- drag-and-drop на agile-доске визуально не реализован;
- уведомления существуют только внутри интерфейса;
- даты, валюта и профиль пока заданы статически.

## Возможное развитие

Следующие логичные этапы:

1. Разделить интерфейс на независимые компоненты и feature-модули.
2. Подключить маршрутизацию и отдельные URL для разделов.
3. Добавить backend, базу данных и синхронизацию между устройствами.
4. Реализовать авторизацию и несколько рабочих пространств.
5. Подключить календарь, банковские API, почту и туристические сервисы.
6. Добавить импорт подтверждений бронирований из писем.
7. Реализовать drag-and-drop для задач.
8. Добавить локализацию и поддержку нескольких валют.
9. Покрыть расчёты и пользовательские сценарии тестами.
10. Добавить offline-режим и PWA-возможности.
